一、项目总目标

对当前 Drupal 网站的视频专区进行一次完整的前台重构和功能完善。

本次必须完成以下六项工作：

1. 视频内容详情页重新设计。
2. 视频列表页重新设计。
3. 视频分类列表页重新设计。
4. 创建独立的视频标签页模板，不再复用图片标签页。
5. 全面审查并重新设计视频播放器。
6. 实现视频时长自动识别、自动保存、自动展示和历史视频批量补齐。

本次目标是打造一个完整、现代、专业的视频内容平台。

不只是更换 CSS，而是需要对页面布局、Twig 模板、组件、数据读取、播放器交互和视频元数据处理进行完整审查与必要改造。

所有修改必须基于当前项目真实架构。

不得猜测现有字段、路由、模板名称和播放器类型。

十二、第十阶段：视频时长自动识别

现有字段：

field_duration

单位：秒。

继续使用现有字段。

禁止创建重复的视频时长字段。

1. 检查 FFprobe

执行：

command -v ffprobe

检查是否存在 FFmpeg / FFprobe。

如果没有：

* 检查系统版本。
* 检查软件包安装情况。
* 评估安装影响。
* 只安装真正需要的组件。
* 不升级其他无关服务。
* 不影响当前 Drupal 运行。

2. 自动检测

Drupal 上传视频后自动检测时长。

读取视频文件实际路径。

通过 FFprobe 获取：

* duration。
* 视频流信息。
* 必要的视频元数据。

本次重点是 duration。

将结果转换为整数秒。

保存到：

field_duration

要求：

* 自动执行。
* 不要求管理员填写。
* 不阻塞内容正常保存。
* 不在前台请求时执行 FFprobe。
* 不读取整个视频文件到 PHP 内存。
* 使用安全的进程执行方式。
* 设置合理超时。
* 限制 FFprobe 执行参数。
* 记录异常日志。

3. 异步队列

优先使用 Drupal Queue API 或项目已有任务系统。

实现：

* 视频上传后加入检测队列。
* 文件实体与任务正确关联。
* 支持重试。
* 防止重复任务。
* 支持任务失败记录。
* 避免阻塞上传请求。
* 视频替换时重新检测。
* 文件删除后正确处理任务。

4. 历史视频补齐

对现有视频进行统计。

输出：

* 视频总数量。
* 已有时长数量。
* 缺失时长数量。
* 文件不存在数量。
* 无法读取数量。

实现历史数据批量补齐。

要求：

* 不修改标题。
* 不修改正文。
* 不修改审核状态。
* 不修改发布时间。
* 不重新上传视频。
* 不改变文件内容。
* 已有有效时长的内容默认跳过。
* 支持分批处理。
* 支持断点续跑。
* 支持重复执行。
* 记录成功和失败数据。

历史数据补齐不能一次性把全部视频加载到内存。

5. 文件来源和权限

本项目可能使用 Drupal Private 文件、S3 File System 和 Cloudflare R2。

必须检查：

* 公共文件。
* 私有文件。
* S3/R2 文件。
