## 3. 问题清单

### AI-01 审核输出被 800 Token 截断

- 所属功能：内容审核、SEO 建议。
- 级别：B。
- 实际现象：文章、图片、视频和 SEO 四次真实调用的完成 Token 都正好是 800。模型调用本身成功，但审核没有进入 `completed`，结果里没有可解析的状态、风险和摘要。
- 根本原因：供应商 `max_tokens` 为 800。DeepSeek 的审核 JSON 实际需要约 1100–2400 个完成 Token。响应被截断后，`ReviewRunner` 无法解析 JSON。
- 影响范围：当时所有走该供应商的审核和 SEO 生成都会失败。内容没有被修改。失败的测试审核记录已随测试内容删除，用量记录 142–145 保留。
- 是否已经修复：是。
- 修复：`xedc_ai_provider.deepseek.max_tokens` 改为 4096；活动配置 `xedc_ai.settings:max_tokens` 改为 4096；新供应商表单默认值和安装默认配置改为 4096。没有改 `config/sync`，没有改表结构。表字段默认值仍是 800，只有插入时省略该列才会用到。
- 修复文件：`web/modules/custom/xedc_ai/src/Form/ProviderForm.php`、`web/modules/custom/xedc_ai/config/install/xedc_ai.settings.yml`。
- 复测结果：通过。文章 1126、图片 1505、视频 1825、SEO 2371 个完成 Token，四次都是 `completed`。指定短文本为 2406，JSON 解析通过。

### AI-02 会员投稿列表漏掉最新待审核修订

- 所属功能：会员投稿审核。
- 级别：B。
- 实际现象：测试稿最新修订已经是 `needs_review`，列表仍找不到它。
- 根本原因：查询要求 `revision_translation_affected = 1`。这次待审核修订该字段为 NULL，更早的草稿反而为 1，于是查到的是草稿，随后被状态条件排除。
- 影响范围：同类会员投稿不会出现在 AI 投稿列表。原生 `/admin/content/moderated` 未改。该查询只读，不写内容。
- 是否已经修复：是。最新修订改为按节点和语言取 `MAX(vid)`，不再使用 `revision_translation_affected`。
- 修复文件：`web/modules/custom/xedc_ai/src/Review/SubmissionModerator.php`。
- 复测结果：通过。新的临时投稿出现在列表中，随后已删除。

### AI-03 测试连接成功时费用一直显示未核算

- 所属功能：费用统计。
- 级别：C。
- 实际现象：连接测试即使模型已有单价，也会按空单价记录，页面提示费用未核算。
- 根本原因：测试连接构造临时模型时把单价写成空字符串。
- 影响范围：只影响“测试连接”这一条用量的费用，不影响审核任务。
- 是否已经修复：是。同供应商、同模型名的启用模型会带上单价。
- 修复文件：`web/modules/custom/xedc_ai/src/Form/ProviderForm.php`。
- 复测结果：通过。用量 141 为 33 输入、9 输出、42 合计、36 微元，与 `0.02 / 4` 的计算公式一致。

### AI-04 缓存 Token 没有单独计价

- 所属功能：费用统计。
- 级别：C。
- 实际现象：原始响应的 `usage` 含 `prompt_cache_hit_tokens` 和 `prompt_cache_miss_tokens`。客户端只读取 `prompt_tokens` 和 `completion_tokens`。
- 根本原因：`OpenAiChatClient::tokens()` 没有读取缓存字段，单价也没有缓存命中价。
- 影响范围：如果厂商对缓存命中另行打折，当前费用会按全部输入 Token 估算，可能高于实际账单。不会少算后继续放行预算。
- 是否已经修复：否。没有厂商缓存单价，不能自行增加一种价格。
- 修复文件：无。
- 复测结果：不适用。

### AI-06 SEO 确认后只写标题和简介

- 所属功能：SEO 建议。
- 级别：E。
- 实际现象：确认写入时，`seo_title` 写入节点标题，`meta_description` 写入 `field_summary`。标签不写入。没有简介字段的视频会拒绝写入。ALT、关键词、分类和结构只出现在建议中。

- 影响范围：不能把 Meta Description 当成已经写入 Metatag。已发布且缺少配置目标语言译文时，写入会被拦住。未确认的建议不会自动写入。
- 是否已经修复：否。这是当前功能边界，不是本次可以静默扩大的写入范围。
- 修复文件：无。
- 复测结果：临时文章上的行为与代码一致，文章保持未发布。

指定短文本正文就是任务要求的那一句。它放在审核提示的正文中，同时附带一条本地检查。返回状态 `attention`，风险 `low`，分数 35，摘要非空。JSON 含 `status`、`risk_level`、`score`、`summary`、`issues`、`suggestions`。响应不含密钥，请求不含图像数据。

同一请求内的用量行共用 Drupal 请求时间，所以 141–145 的入库时间相同，146–149 也相同。表中的调用时间优先使用脚本实际完成时间。

已入库费用合计 49,817 微元，即 0.049817 元。三次未入库调用按同一单价估算 5,193 微元。全部真实调用合计约 0.055010 元。这个数字不是厂商账单。

指定短文本的调用次数使内容审核用量增加 1。概览能读到今日调用、月费用和包含零值在内的 14 天序列。

## 5. 分项结果

### 内容审核

临时文章读取到标题、正文和简介。过短标题由本地规则报“标题过短”，并单独保存在 `local_checks`，不依赖另一篇内容的 AI 结论。图片只发送标题和简介等文字，本地结果含 SHA-256 和 pHash，视觉开关为关闭。视频发送标题和正文文字，本地结果有 SHA-256、没有 pHash，并说明没有抽取画面。三种内容审核完成后都保持未发布。

### 重复检测

两份相同测试图片 SHA-256 相同，不同图片不同。相同图片 pHash 距离为 0，不同图片大于阈值 10。视频文件不算 pHash。测试文件小于 64MB。临时文件和空目录已删除。没有删除或改动生产文件。

### 投稿审核

工作流 `xedc_editorial` 存在 `needs_review` 到 `published` 的转换。退回保存后为 `changes_requested`，拒绝保存后为 `rejected`，两者都未发布。拒绝原因为空时不会保存。未确认不会改变状态。编辑和普通会员不能打开投稿页。

没有保存“通过”。原因是发布会让节点进入已发布状态，并可能调用 `xedc_auto_translate` 的 Microsoft Translator 或 DeepL。

### 翻译建议

翻译任务可以入队，目标语言记在任务备注中。取消后节点没有新增译文。没有调用翻译模型，也没有触发 DeepL 或全站翻译。`xedc_ai` 在这次测试中没有覆盖真实翻译。

### 预算、暂停和队列

暂停标志置位后，任务在调用模型前返回，模型调用次数不变。待执行任务可以取消。每日预算临时改为 0 时，自动调用被拒绝；未打开手动超预算时，手动调用也被拒绝。配置随后恢复为每日 2.00 元，手动调用恢复允许。暂停标志已恢复为关闭。

模拟自测还覆盖了失败、可重试错误、重试上限、忽略、结果缓存、备用模型、并发延迟和中断。这些不是真实 DeepSeek 调用。

## 6. 生产上线建议

**可以有限试运行。**

依据：

- 已保存的模型、地址和密钥可用。`deepseek-flash` 对 `https://api.deepseek.com/chat/completions` 返回 HTTP 200。
- 文章、图片文字、视频文字和 SEO 建议在输出上限提高到 4096 后都能完成，并且不发布内容。
- 本地规则与 AI 结果分开保存。图片和视频没有发送文件，也没有抽帧。
- 投稿列表漏检已修复。退回和拒绝使用现有工作流，未确认不能提交。
- 用户 1 之外的编辑、会员和匿名用户不能打开 AI 管理路由。内容编辑角色没有 AI 权限。
- 预算和暂停在隔离测试中能挡住模型调用。自动审核保持关闭。

不能写成“可以正常投入使用”，因为：

- SEO 确认后只写标题和简介，Meta Description 会进入简介字段，不会进入 Metatag。
- 重复页不显示内容引用。
- 缓存 Token 没有单独计价，已保存单价也还没有管理员确认。
- “通过投稿”没有做真实保存。全站 cron 和浏览器操作没有执行。
- 翻译建议只验证了入队和取消，没有生成真实译文。
- 五个任务模型配置为空，目前全部使用默认模型。这是当前配置的结果，不是按任务分别选择的模型。

不需要先停用。建议试运行时保持自动审核关闭，只对临时或草稿内容手动审核，并先确认单价。
