# 测试计划

状态只使用 PASS、FIXED、FAIL、NOT TESTED、BLOCKED。连续两轮都要是真实执行，不能把上一轮结果抄成第二轮。

## 隔离要求

- 不修改 `/var/www/drupal`、生产数据库、Nginx、PHP、MariaDB、Redis、systemd、cron、`/root/backup.sh`、Cloudflare 或生产 R2。
- 安装、导入和恢复只在独立容器里做。容器不使用特权模式、host 网络、docker.sock，也不挂载生产目录。
- `--force` 不能作为通过条件。

## 必测场景

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| S1 | 生产路径、3306、安装、定时任务、管理员重置 | 即使带 `--force` 也退出码 3 |
| S2 | 加密往返和错误密钥 | 正确密钥还原，错误密钥失败 |
| S3 | 全量加增量恢复 | 文件、删除、lab 隔离和 settings 改写正确，manifest 不含测试口令 |
| S4 | 路径穿越、越界符号链接、包内硬链接 | 穿越和越界链接被拒绝，硬链接复制成普通文件 |
| S5 | 嵌套 `node_modules` | 新备份不收入该目录 |
| S6 | settings 注释与真实配置 | 只改最后一处真实配置 |
| S7 | PHP 域名重写 | 自测 PASS |
| S8 | 自签证书、nginx 测试、错误配置回滚 | `nginx -t` 通过，回滚后再通过 |
| S9 | 定时任务渲染和一次性登录链接 | 只写临时目录 |
| S10 | S3 签名 | 与 AWS 公开测试向量一致 |
| S11 | 分段上传、下载、校验、恢复 | 本地 S3 服务上哈希一致 |
| S12 | 域名迁移 | 演练库上第一次改写、第二次 0 行、回滚后旧地址回来 |
| S13 | 生产只读加密备份 | `backup verify` 为 PASS |
| S14 | 全新 Ubuntu 24.04 恢复 | 安装 PHP 8.5、Nginx、MariaDB 13，导入后首页和登录页可用 |
| S15 | S14 再跑一遍 | 连续第二轮 DRILL_OK |

S10 使用公开测试向量。S11 不连接生产 R2。S14 使用 `--role lab`。
