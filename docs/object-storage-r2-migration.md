## 界面和执行器

`StorageMigrationForm` 可以选择来源：本地公开加私有、仅 `public://`、仅 `private://`、已有 `s3://`。按钮是“执行预检查”和“生成完整清单”，以及取消。完整清单会 HEAD 目标键。页面上没有复制按钮。

`MigrationExecutor` 注册为 `xedc_core.storage_migration_executor`。复制仍然要求本次请求明确确认，Runtime 打开时也不会自动搬文件。它的规则是：

1. 先写清单到 `xedc_storage_migration_item`。
2. 复制前再算 SHA-256。源文件在复制过程中变了就失败，不改 URI。
3. 私有文件在 CDN 仍可能公开读到私有前缀时，不复制。
4. 上传用途是 `migration`，键必须落在 `s3fs-public/` 或 `s3fs-private/`。私有 URI 不会进公开前缀。
5. 成功状态是 `verified`。文件实体 URI 不变，本地文件保留。
6. 回滚只删除该任务记录过、且哈希匹配的远程对象。
7. 没有任务记录的对象不会被回滚删除。Bucket 里那 1 个未知对象不在此列。

表由 `xedc_core_update_10007` 创建。这次清单写入了公开和私有两组行，状态是待复制或缺失，不是已迁移。

## 还不能做的操作

不要在启用 Runtime 时自动开迁。不要先删本地文件。不要在上传失败时改 `file_managed.uri`。全量复制、按类型、按日期、分批、暂停和继续都要等人工确认后再从执行器跑，并且先用一小批公开文件验证键名 `s3fs-public/` + 相对路径。
