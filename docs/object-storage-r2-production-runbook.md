# 生产接入运行手册

日期：2026-11-02。本手册只定义以后的顺序。本轮没有执行复制、URI 修改、接管或 Cloudflare 变更。

2026-11-02 19:06 UTC 的复制前门禁：WAF 已通过，PNG/MP4 的 GET 仍是 `max-age=3600` 而不是对象上的 60 秒，阶段 A 没有执行。详见 `docs/object-storage-r2-public-migration-report.md`。

当前不允许进入阶段 A，也不允许进入阶段 F。公开文件的本地副本和哈希已经齐备，但 WAF 双重编码仍能匿名读到桶内测试对象，图片和视频的边缘缓存头仍被改写，`r2.dev` 也还没有程序可核验的关闭证据。

## 现在必须保持的状态

- `XEDC_STORAGE_RUNTIME`、`STORAGE_I_UNDERSTAND_TAKEOVER`、`STORAGE_PUBLIC_TAKEOVER`、`STORAGE_PRIVATE_TAKEOVER`、`STORAGE_CDN_ENABLED` 全部关闭。
- `public://` 保持 `Drupal\Core\StreamWrapper\PublicStream`。
- 不修改 137 条 File Entity URI。
- 不删除本地文件，不删除来源不明的 R2 对象。
- S3FS 的 hostname、domain 和两个接管开关保持现状。

## 开始任何复制之前

1. 按 `docs/object-storage-r2-waf-final-test.md` 收紧 WAF，并用新的测试对象复测。规范路径、`%2F`、`%252F`、大小写、多余斜杠和查询参数都要是 403，正文不能含测试标记。
2. 在 Cloudflare 把 Browser Cache TTL 设为 Respect Existing Headers，并确认没有 Cache Rule 把图片或视频改成 `max-age=14400`。用新的测试 PNG 和 MP4 上传 `public, max-age=60`，GET 必须仍是 60，不能只看 HEAD。
3. 在 R2 控制台确认 Public Development URL（`r2.dev`）已禁用。配置文件里没有这个主机名，不能代替控制台确认。
4. 五个开关仍是关闭。复制不依赖接管。

## 阶段 A：复制公开文件，不改 URI

前置条件：上一节三项都已复测通过。只复制清单里 `ready=yes` 的 128 个公开文件。目标键是 `s3fs-public/` 加相对路径。写入头使用 `CachePolicy::forObject()`，现有文件名得到 `public, max-age=3600`，不是一年 immutable。

执行：按清单逐个复制。远程键已存在且 SHA-256 不同则停止该文件，不覆盖。不改 `file_managed`。

验证：目标对象数 128，字节合计 75,177,632，哈希与清单一致。站点页面仍从 `gitxx.xyz` 的本地文件打开，HTML 里没有 `cdn.gitxx.xyz`。

失败：停止后续复制。保留已写入且校验通过的对象，记录未完成的 fid。不删除本地文件。

回滚：本地文件本来就还在，URI 未改，流量不受影响。只删除本阶段新写入且能对上清单键的对象。不对不上清单的对象不动。

## 阶段 B：数量、大小和 SHA-256

前置条件：阶段 A 结束，且没有未解释的覆盖。

执行：对 128 个键做 HeadObject，并重新读取对象字节计算 SHA-256。和清单、本地文件两边对比。

验证：128 个都存在，字节和哈希一致，没有多余的 `s3fs-public/` 生产键。测试前缀仍是空的。

失败：不一致的键标记为不可接管。不自动覆盖，不改 URI。

回滚：与阶段 A 相同。只删除能对上清单、且确认是本阶段写入的键。

## 阶段 C：私有文件

前置条件：9 个缺失压缩包有了真实来源，或者已经人工决定永久放弃。当前没有来源，不能开始。

执行：只复制本地重新出现、并能算出 SHA-256 的私有文件。目标键在 `s3fs-private/`。缓存头使用 `private, max-age=0, no-store`。复制后从 CDN 匿名访问，必须是 403 且正文不是文件内容，包括 `%252F` 变体。

验证：匿名请求失败，登录后的受保护下载仍走 Drupal 权限检查。运行时未开时，预签名入口应继续拒绝。

失败：任何一个私有对象能被匿名读到，就停止，并删除本阶段新写入的私有测试键或已确认的复制键。

回滚：删除本阶段写入的 `s3fs-private/` 键。本地文件和 URI 不动。

## 阶段 D：图片样式

前置条件：阶段 B 通过，接管仍然关闭。

执行：不上传现有 766 个衍生文件。选一个已有源图和一个正在使用的样式，在仍为本地流时确认衍生文件可以再生。接管测试放到阶段 E，并且只用测试源图，不切换全站。

验证：本地 `public://styles` 的 766 个文件还在。没有为了迁移删除它们。

失败：不能再生时，保持本地样式目录，不进入接管。

回滚：样式目录本来没有被删，不需要恢复对象。

## 阶段 E：小批量灰度

前置条件：A、B 通过，WAF 和缓存复测仍通过。私有文件要么已安全复制，要么明确排除。

执行：仍不打开五个开关。用少量公开测试对象确认 CDN URL、Range 和缓存头。生产页面继续走本地文件。灰度如果要打开开关，只能在单独确认的维护窗口，并且先只覆盖一个明确的测试 URI，不把现有 128 个文件的流量切过去。

验证：测试对象的 GET 缓存头与源站一致，私有变体仍是 403，生产首页和内容页没有 CDN 主机名。

失败：立刻把开关设回关闭并重载 PHP-FPM。本地流会恢复。已复制对象可保留，因为 URI 还没改。

回滚：关闭五个环境变量，重载 PHP。不改 URI，不删本地文件。

## 阶段 F：接管评估

前置条件：E 的灰度记录通过，`r2.dev` 已由管理员确认关闭，缓存头不再被改成 14400，私有前缀的编码变体都是 403。`TakeoverReadiness` 不能单独当作已经接管。

执行：才讨论按顺序打开 `XEDC_STORAGE_RUNTIME`、确认开关、公开接管、CDN 改写。私有接管单独评估。打开后 `public://` 会变成 S3FS 流，这一步会改变现有存储行为，所以不在本轮授权范围内。

验证：新上传进入对应前缀，旧 URI 不用改写，页面公开资源来自 `cdn.gitxx.xyz`，私有资源不出现在 CDN URL 中。图片样式能在公共前缀生成。

失败：关闭全部五个开关并重载 PHP-FPM。本地文件仍是回滚副本。

回滚：关开关，重载 PHP。不要把 CDN 域名写进 S3FS domain。不要把 File Entity 改成 `s3://`。
