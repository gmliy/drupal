# AI 运营中心

本文说明当前 Drupal 11 站点的 AI 运营中心。实现位于自定义模块 `xedc_ai`。它负责外部文本模型、内容审核建议、重复文件检测、会员投稿处理、SEO 建议、用量统计和操作日志。

模块与 `xedc_core` 分开。`xedc_core` 继续负责文件、对象存储和清理。AI 运营中心有自己的数据表、队列、密钥存储和后台页面。内容翻译仍由 `xedc_auto_translate` 执行，本模块只生成翻译建议，不替换现有翻译服务。

后台入口：管理 → AI 运营中心，地址 `/admin/xedc/ai`。

Drupal 原生内容审核仍在 `/admin/content/moderated`。AI 审核中心展示建议，并在会员投稿上调用现有工作流 `xedc_editorial` 的转换。它不替换、不删除这个页面，也不修改工作流配置。

## 2. 安全边界

所有外部请求都走 `OpenAiChatClient`。控制器只负责页面和表单，不直接请求模型。

当前行为：

- 只把标题、描述、分类、标签和相关文字字段发给模型。
- 图片和视频文件留在服务器上做本地检查。第一阶段不调用视觉模型，也不抽取视频画面。
- 视觉审核接口 `VisionAuditInterface` 已预留，当前实现 `DisabledVisionAudit` 始终关闭，不读取文件。
- API Key 不写入 Git、普通配置、前端 JavaScript 或普通日志。页面只显示末四位。
- AI 返回的 JSON 只作为审核报告保存。它不会被当成 PHP、SQL 或命令执行。
- 默认不自动发布、删除、拒绝或覆盖内容。自动审核开关在运行配置里，安装默认值全部关闭。
- 写入标题或简介、以及变更投稿状态，都要求管理员确认。
- 同一条审核使用 Lock API 避免并发重复执行。大量内容进入队列 `xedc_ai_review`，不在一次 HTTP 请求里同步调用模型。

## 3. 模型与密钥

供应商采用 OpenAI Compatible API。预设包括：

| 标识 | 名称 | 默认 Base URL |
| --- | --- | --- |
| `deepseek` | DeepSeek | `https://api.deepseek.com/v1` |
| `openai` | OpenAI | `https://api.openai.com/v1` |
| `dashscope` | 阿里云百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| `siliconflow` | 硅基流动 | `https://api.siliconflow.cn/v1` |
| `volcengine` | 火山引擎 | `https://ark.cn-beijing.volces.com/api/v3` |
| `zhipu` | 智谱 AI | `https://open.bigmodel.cn/api/paas/v4` |
| `moonshot` | Moonshot AI | `https://api.moonshot.cn/v1` |
| `custom` | 自定义 OpenAI Compatible API | 由管理员填写 |

每个供应商可配置名称、Base URL、API Key、模型名称、超时、最大 Token、温度、启用状态和是否默认。模型可标记能力：文本审核、内容质量分析、SEO 建议、翻译、通用文本处理。

任务实际使用运行配置里为该任务选定的模型。没有单独指定时，使用默认模型。能力标签用于展示和筛选，不会在请求时自动改选模型。

密钥读取顺序：

1. 环境变量 `XEDC_AI_KEY_{供应商标识大写}`，例如 `XEDC_AI_KEY_DEEPSEEK`。
2. Key 模块中的文件型密钥 `xedc_ai_{供应商标识}`。

密钥文件放在私有目录 `private://xedc-ai-keys/`，目录权限 `0700`，位于 Web 根目录之外。保存新密钥时，留空表示保留原密钥。

客户端会处理超时、限流、鉴权失败、模型不存在、无效 JSON 和网关错误。可重试的失败会延迟重新入队，达到重试次数后记为失败并保留原因。没有单价的模型不编造费用，用量里标记为未核算。

## 4. 审核流程

支持的内容类型是文章 `article`、美图 `photo`、视频 `video`。

一次审核按这个顺序进行：

1. 管理员单选或批量选择内容，或由已开启的自动开关在新建时入队。
2. 本地规则检查文字、分类、标签、文件和时长。
3. 计算 SHA-256。图片再计算 pHash。
4. 收集标题、描述、分类和标签。
5. 按任务调用对应模型。
6. 校验并解析 JSON。
7. 生成审核报告并追加一条记录。
8. 管理员在详情页查看问题和建议。
9. 管理员确认后，才把允许的字段写入内容。

重复审核新增记录，不覆盖旧记录。内容未变化、规则版本和模型未变化时，可以复用上一次结果，避免重复调用。管理员手动重新审核会跳过这次复用。

队列名是 `xedc_ai_review`，由 cron 每次最多处理约 30 秒。暂停开关保存在状态 `xedc_ai.paused`。暂停后，尚未执行的任务保持待审核，不会调用模型。取消只作用于仍处于待审核的任务，并把对应队列项移除。

本地文件扫描使用另一条队列 `xedc_ai_local`。打开重复检测页面不会当场哈希大量文件。页面上的扫描每次最多提交 20 个内容编号。

## 5. 审核结果

队列表保存任务状态。详情页另外显示给管理员看的结论。

任务状态：

| 存储值 | 显示 |
| --- | --- |
| `pending` | 待审核 |
| `processing` | 审核中 |
| `completed` | 审核完成 |
| `failed` | 审核失败 |
| `ignored` | 已忽略 |
| `cancelled` | 已取消 |

风险等级：`normal` 正常，`low` 低风险，`medium` 中风险，`high` 高风险。

完成后的页面结论：

- 已确认或已忽略：已处理
- 高风险，或模型结果为失败：存在风险
- 中风险，或结果为需要关注：需要修改
- 低风险、正常，或结果为通过：审核通过
- 其余已完成结果：人工复核

每条记录保留内容 ID、类型、标题、时间、模型、任务类型、风险、质量分、问题、建议、Token、估算费用、执行状态和操作管理员。

模型输出使用固定 JSON 结构。解析器接受代码块中的 JSON，拒绝非法状态，并单独识别模型拒绝回答、超时、限流和 Token 超限。无效 JSON 记为审核失败，不修改内容。

## 6. 本地规则与重复检测

本地规则不依赖模型和 API 额度。配置在 `xedc_ai.rules`，后台可改：

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `min_title` | 4 | 短于这个字数的标题记为过短 |
| `max_title` | 80 | 标题上限 |
| `min_article_body` | 40 | 文章正文最短长度 |
| `max_tags` | 12 | 标签数量上限 |
| `min_image_edge` | 200 | 小于这个边长记为图片尺寸较小 |
| `max_video_seconds` | 86400 | 超过这个秒数记为时长不合理 |
| `phash_distance` | 10 | 小于或等于这个距离时提示疑似重复 |
| `max_hash_bytes` | 67108864 | 超过 64MB 的文件不计算哈希 |

本地检查包括空标题、空描述、缺失内容字段、无效分类、无效标签、无效文件、异常大小、重复 SHA-256、疑似 pHash、不合理视频时长、空正文和明显格式异常。广告或垃圾短语会记为文字问题。

重复检测：

- SHA-256 表示文件字节完全相同，适用于图片和视频。
- pHash 只用于图片近似重复，结果是疑似提示，不直接判定两张不同文件一定重复。
- 视频第一阶段只有 SHA-256，不做画面相似度。
- 审核不会为了检查而完整解码视频。

## 7. 三类内容怎么审

美图检查标题、描述、SEO 描述、标签、分类、人物名称和字段完整性，同时做 MIME、扩展名、大小、完整性、尺寸、SHA-256 和 pHash。不分析画面。

视频检查标题、简介、SEO 描述、标签、分类、人物名称、时长、大小和格式，同时做 MIME、扩展名、完整性、SHA-256 和时长字段。视频没有独立简介字段时，正文字段 `field_body` 当作描述。不分析画面。

文章检查标题、正文、完整性、语义、SEO 描述、关键词、分类、标签、重复风险、广告和低质量文字。AI 只给报告和修改建议。

## 8. 会员投稿

投稿列表读取工作流 `xedc_editorial` 中，最新修订状态为 `needs_review` 的文章、美图和视频。作者不是管理员或内容编辑时，才算会员投稿。

列表显示投稿人、时间、类型、本地缺口、已有 AI 审核和历史。管理员可以批量加入 AI 文字审核。通过、退回修改和拒绝必须勾选确认。拒绝必须填写原因。

状态变更使用现有转换，不改工作流本身：

| 操作 | 目标状态 |
| --- | --- |
| 通过 | `published` |
| 退回修改 | `changes_requested` |
| 拒绝 | `rejected` |

这些状态里，只有 `published` 会成为默认修订并发布。退回和拒绝保持未发布。当前工作流不允许的转换会被拒绝，并说明工作流配置没有被修改。

因为待审核、退回和拒绝不是默认修订，列表和状态判断读取最新修订，而不是 `Node::load()` 返回的默认修订。

## 9. SEO 与翻译

SEO 页面做两件事：

- 为单篇内容生成标题、Meta 描述、ALT、简介、标签、分类、关键词和结构建议。
- 读取最近一份已保存的 Site Audit 报告。打开页面不会重新扫描全站。

管理员确认后，当前可以写入的字段是标题，以及内容类型上真实存在的 `field_summary`。Meta 描述建议写入简介，因为 Metatag 没有单独的可写存储字段。视频没有简介字段时，不会写入简介。已发布且仍缺少自动翻译目标语言的内容不会写入，避免触发现有翻译流程。ALT、标签和分类目前只出现在建议里，确认后不会自动改这些字段。

AI 翻译管理把指定内容和目标语言加入翻译建议队列。发布用的译文仍由 AI 自动翻译模块处理。

## 10. 概览、用量和日志

运营概览的数字来自数据库，没有演示数据。卡片包括今日审核、累计审核、待审核、审核通过、需要修改、高风险、审核失败、重复文件、今日 API 次数、今日 Token 和本月估算费用。

图表包括近 14 个本地日的审核趋势、内容类型分布、风险分布、模型 Token 和费用趋势。没有记录的日期按 0 计入趋势。通过和需要修改按已完成记录的风险等级归类。

用量页可以按供应商、来源和状态筛选。费用以微元保存，1 元等于 1,000,000。未填写单价的调用不生成估算费用。

操作日志记录管理员、时间、对象、操作类型、修改前后的值、AI 建议、是否人工确认和执行结果。日志文本会去掉密钥样式的字符串。

达到每日或每月预算后，自动调用暂停。手动调用是否允许超出预算，由运行配置决定。

## 13. 日常操作

1. 用有模型管理权限的账号打开 AI 模型管理，新增供应商并保存密钥。
2. 在供应商页面执行连接测试。失败时查看错误类型，页面和日志都不应出现完整密钥。
3. 添加模型，填写模型名、超时、最大 Token、温度和每百万 Token 单价。
4. 打开 AI 运行配置，选择默认模型和各任务模型，确认自动审核开关保持关闭，直到运营流程确认可用。
5. 在 AI 内容审核中选择文章、美图或视频，加入队列。
6. 执行 cron，或手动处理队列：

```bash
vendor/bin/drush queue:run xedc_ai_review
vendor/bin/drush queue:run xedc_ai_local
```

7. 打开审核详情，查看本地结果、重复提示、评分、问题和建议。
8. 需要改标题或简介时，由拥有「执行内容修改」权限的管理员确认后写入。
9. 会员投稿在会员投稿审核中处理。先看缺口和 AI 建议，再确认通过、退回或拒绝。

## 14. 验证

仓库没有 `phpunit.xml`，不能用 PHPUnit 作为本模块的通过标准。

语法检查：

```bash
find web/modules/custom/xedc_ai -name '*.php' -print0 | xargs -0 -n1 php -l
```

功能自测使用模拟 HTTP，不访问真实模型，也不打印密钥：

```bash
vendor/bin/drush php:script web/modules/custom/xedc_ai/tests/manual/ai-self-test.php
```

自测覆盖密钥保存和读取、密钥脱敏、连接成功和失败、超时、限流、无效 JSON、空标题、空描述、SHA-256、pHash、视频文件检查、单条审核、失败重试、暂停、取消、审核记录、人工确认后的字段写入、未授权拒绝、投稿确认、SEO 建议、用量统计、日志，以及原生审核路由仍在。

真实厂商的连通性需要在模型管理页面用实际密钥单独测试。自测通过不能代替这一步。

## 15. 当前限制

- 确认后自动写入的字段是标题和 `field_summary`。ALT、标签和分类需要管理员按建议手工处理。
- 批量进度通过队列状态和审核详情查看。
- 概览中的通过和需要修改按风险等级统计。
- 重复检测页面一次最多把 20 个内容编号送入本地扫描队列。pHash 对比读取最近的图片哈希，并限制返回的疑似配对数量。
- 第一阶段没有视觉审核和视频抽帧。需要时再启用独立的视觉插件，当前关闭实现不影响现有审核。
